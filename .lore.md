## Long-term Knowledge

### Architecture

<!-- lore:01a19ff3-b3d7-7e3a-8851-dec2d09c5464 -->
* **.prekignore excludes fragments/ from prek discovery (APT-22, load-bearing)**: agentic-project-template keeps fragments/ as per-tool merge-input data (fragments/tools/\<tool>/{mise.toml,prek.toml,agents.md,gitignore.txt,wt.toml}) — never hook configs for this repo. Root .prekignore (pattern \`fragments/\`) is load-bearing: without it prek discovers fragments/tools/{alint,tombi}/prek.toml as workspace projects and \`prek run --all-files\` (mise run lint) fails — alint-check exits 2 ('no .alint.yml found'). Chosen over renaming fragment configs to non-discoverable names like prek-layer.toml (rejected: per-tool dirs named prek.toml are cleaner for the CLI merge step) and over root \`exclude\` (rejected: filters hook inputs, not discovery). .prekignore lives at repo root, not template/, so it is not stamped into generated projects; stamped projects get one merged prek.toml and need no ignore file.

<!-- lore:01a1a361-cb43-798c-8d68-577fcc36e06f -->
* **ARCHITECTURE.md layer stack: spec wins, bottom-up read, opt-in boundaries (git-ai, consult-llm)**: ARCHITECTURE.md conventions: spec.md wins over ARCHITECTURE.md on disagreement; the stack is read bottom-up (BASE owns language/build/test/lint; the agentic layer owns L1-L7). L7 attribution = git-ai (opt-in) + docs/experiments.md; merge.squash=false is pinned in project config. L5 task mgmt = \`backlog init\` via the idempotent backlog-init mise task. L6 'Structure & content hygiene' = alint bundled rulesets + project .alint.yml; when a dedicated tool wins, the alint rule is switched off. The CLI invokes copier and never reimplements it; the endgame is a dotagents approach. Skills are stamped always (2-3 default skills); consult skills only with consult-llm, which is opt-in and default off (pinned by test\_consult\_llm\_is\_opt\_in\_default\_off, tests/test\_stamp.py ~line 45). One concern (attribution cron) deliberately runs at user level via chezmoi, never in the project.

<!-- lore:01a1a547-1c6b-7da0-b30f-6ec5137d99a3 -->
* **merge.py design: one deep\_merge primitive + thin per-format wrappers; unified pipeline rejected (YAGNI, copier-cat C1)**: merge.py layering: deep\_merge is the single universal primitive (type-agnostic over dicts from TOML/JSON/YAML alike); merge\_toml\_file, merge\_json\_file, \_merge\_rendered (YAML) are thin load/dump wrappers with no policy; merge\_mise\_fragment is the ONE wrapper carrying extra rules (the two provenance migrations). A unified PIPELINES registry (file kind → primitive + pre-merge policy list) was sketched 2026-11-03 and REJECTED: (1) the spec pins the CLI thin — the engine is the prototype for copier-cat's C1 and must stay readable as a spec artifact; (2) only one file kind has policies — a registry is machinery for a single user; (3) YAGNI — generalize when a second policy-bearing kind appears. Extension paths: a second backend move (e.g. alint github:→http:) → loop the bare-key deletion over overlay's backend:tool keys; install script changes → append the outgoing script to the registry. A dev-time tripwire test (walk git log over the fragment; assert every historical install.run is current or registered) was proposed, awaiting user approval — not implemented.

### Decision

<!-- lore:01a1a345-fa33-75b1-98f2-a068d92749b5 -->
* **LSP support: L0 mise pins + per-agent wiring, no cross-agent abstraction (apt-9 decision-2)**: decision-2 (backlog/decisions/, accepted 2026-11-03): language servers are environment tools pinned in per-tool mise fragments (L0) like any binary, resolved via mise shims; wiring into an agent is that agent's L2 concern — opencode gets the \`lsp\` section in .opencode/opencode.json via RENDERED\_SHARED. Rejected: a new layer or cross-agent abstraction — the contract ('mise-pinned binary on PATH + per-agent config stanza') is too thin to abstract; claude/codex/cursor wiring is per-agent notes tracked as apt-11. apt-10 shipped: pyright pinned npm:pyright@1.1.414, alint lsp as the only explicit stanza. CAVEAT (apt-10 AC4 smoke): opencode V2 2.0.32 runs no LSP servers — the stanza is forward wiring; the working diagnostics path is running the pinned CLIs directly \[\[01a1a362-39af-79ab-8af5-379c78212f9b]]. spec.md SHALL: the layer never installs servers at stamp time beyond the pin. backlog/decisions/ ADRs are deliberately separate from spec.md's Decision record snapshot table.

<!-- lore:01a19ff3-b423-7ba8-a0b9-afe92162d50f -->
* **prek layer merge invariant: never silently drop existing hooks**: Design invariant (fragments/prek-layer.toml header, recurring across sessions): the CLI merging \[\[repos]] entries into a stamped project's prek.toml must never silently drop existing hooks; it creates prek.toml if absent, and for a legacy .pre-commit-config.yaml it appends in that file's own format instead of replacing it. Rationale: fragments are additive layers over user project config — silently dropping hooks would remove enforcement the user already had.

* **non-interactive permission rejections: use uv run prek from repo venv**: In non-interactive agent runs, shell commands that would prompt for permission are rejected ('This non-interactive run cannot ask the user for permission...'). Rejected: \`mise exec\`, invoking the prek binary from the mise installs dir, and COMPOUND commands (for-loops, \`$()\` subshells with \`>\` redirects — batch \`git show\` extraction loops all failed). Works: \`uv run prek\`/\`uv run python\` from the repo venv, single \`git show \<sha>:\<path>\` commands, the file-creation tool. Workaround for bulk git-history extraction: write a Python script via the write tool to ~/.cache/tmp/opencode/ (outside the repo, keeps the worktree clean), run \`uv run python script.py\`, and let the script invoke git via subprocess. Also: scratch test worktrees under ~/.cache/tmp/opencode are cleaned up with \`git worktree remove --force\` (own scratch, not user work).

* **prek workspace discovery: exact config filenames, .prekignore scope, cache --refresh**: prek (j178/prek, pinned 0.5.2 in agentic-project-template mise.toml) workspace discovery only recognizes configs named exactly \`prek.toml\` or \`.pre-commit-config.yaml\` — e.g. \`prek-layer.toml\` is never discovered (verified empirically). \`.prekignore\` at repo root excludes directories from discovery but does NOT remove files from an ancestor project's candidate files: root hooks (tombi-format, trailing-whitespace, etc.) still process fragments/\*.toml. Trap: root config \`exclude\` looks like the equivalent fix but filters files passed to hooks, not discovery. * **test\_lsp\_servers\_resolve\_through\_shims: alint Popen unbounded reads, Content-Length in chars not bytes**: Gotcha in tests/test\_stamp.py (~line 113): the alint branch uses Popen + unbounded p.stdout.readline()/read(length) with NO timeout — a slow or hung alint wedges the whole suite (no pytest timeout configured); the pyright branch has timeout=60. Also assumes Content-Length is the FIRST header line (LSP spec allows any header order; works because pinned alint 0.21.0 sends it first). Trap: looks fine because tests pass with the pinned binary on ASCII paths. Fix: subprocess.run(input=payload, timeout=30) and compute length from data.encode('utf-8').

### Pattern

<!-- lore:01a19ff1-6e6d-7d52-8d40-567630920919 -->
* **Agent Skill Installation via dotagents**: Skills are authored via the skillet flow in ai-prompt-library (spec.md → SKILL.md). dotagents resolves skills from GitHub, so the push must precede installation. In the template's stamped bootstrap (fragments/mise-layer.toml), dotagents is mise-pinned (\`mise install "npm:@sentry/dotagents"\`) then installed project-scope via \`dotagents --project install\` — no dedicated dotagents-install mise task exists.

<!-- lore:01a19ff3-b466-7a88-9b4e-2a116b7dc0dd -->
* **agentic-project-template conventions: apt-ID comments, mise lint tripwire, template/ jinja-only**: agentic-project-template conventions: (1) comments in config files must reference the apt task ID (repo ai-rules; .prekignore cites apt-22); (2) \`mise run lint\` = \`uv run prek run --all-files\` — the natural tripwire for prek config regressions; prek pinned 0.5.2 in mise.toml; (3) template/ holds only .jinja files — no discoverable prek configs exist outside fragments/; (4) hooks installed via \`prek install\`; (5) repo test suite is merge-logic unit tests + stamp matrix — config-only changes need no new test. Test commands: \[tasks.test] = \`uv run pytest tests/ -x -q\`. The \[tasks.test-template] stamp matrix stamps $root/existing via \`layer --non-interactive\`, $root/fresh via \`new --base "$PWD" --non-interactive\`, and an update path (stamped with --set include\_git\_ai=true, git fixture commit, then \`update\`, then grep include\_git\_ai → 'update smoke OK (choices preserved)'); update smoke is skipped if the template repo has no commits.

<!-- lore:01a19ff1-6e5b-7355-a7d0-e1a30c94c833 -->
* **Backlog Task Management Workflow**: The project uses a structured task system defined in \`backlog/config.yml\` with statuses: To Do, In Progress, Done. Task files (e.g., \`apt-24\`) contain metadata like \`id\`, \`title\`, \`created\_date\`, and \`updated\_date\`. The \`backlog-py\` CLI does not use a \`task complete\` verb; closing a task is done via \`task edit -s Done --append-notes\`.
