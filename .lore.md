## Long-term Knowledge

### Architecture

<!-- lore:01a19ff3-b3d7-7e3a-8851-dec2d09c5464 -->
* **.prekignore excludes fragments/ from prek discovery (APT-22, load-bearing)**: agentic-project-template keeps fragments/ as per-tool merge-input data (fragments/tools/\<tool>/{mise.toml,prek.toml,agents.md,gitignore.txt,wt.toml}) — never hook configs for this repo. Root .prekignore (pattern \`fragments/\`) is load-bearing: without it prek discovers fragments/tools/{alint,tombi}/prek.toml as workspace projects and \`prek run --all-files\` (mise run lint) fails — alint-check exits 2 ('no .alint.yml found'). Chosen over renaming fragment configs to non-discoverable names like prek-layer.toml (rejected: per-tool dirs named prek.toml are cleaner for the CLI merge step) and over root \`exclude\` (rejected: filters hook inputs, not discovery). .prekignore lives at repo root, not template/, so it is not stamped into generated projects; stamped projects get one merged prek.toml and need no ignore file.

<!-- lore:01a1a361-cb43-798c-8d68-577fcc36e06f -->
* **ARCHITECTURE.md layer stack: spec wins, bottom-up read, opt-in boundaries (git-ai, consult-llm)**: ARCHITECTURE.md conventions: spec.md wins over ARCHITECTURE.md on disagreement; the stack is read bottom-up (BASE owns language/build/test/lint; the agentic layer owns L1-L7). L7 attribution = git-ai (opt-in) + docs/experiments.md; merge.squash=false is pinned in project config. L5 task mgmt = \`backlog init\` via the idempotent backlog-init mise task. L6 'Structure & content hygiene' = alint bundled rulesets + project .alint.yml; when a dedicated tool wins, the alint rule is switched off. The CLI invokes copier and never reimplements it; the endgame is a dotagents approach. ### Decision

<!-- lore:01a1a345-fa33-75b1-98f2-a068d92749b5 -->
* **LSP support: L0 mise pins + per-agent wiring, no cross-agent abstraction (apt-9 decision-2)**: decision-2 (backlog/decisions/, accepted 2026-11-03): language servers are environment tools pinned in per-tool mise fragments (L0) like any binary, resolved via mise shims; wiring into an agent is that agent's L2 concern — opencode gets the \`lsp\` section in .opencode/opencode.json via RENDERED\_SHARED. Rejected: a new layer or cross-agent abstraction — the contract ('mise-pinned binary on PATH + per-agent config stanza') is too thin to abstract; wiring for claude/codex/cursor is per-agent notes tracked as apt-11. apt-10 implemented this: pyright pinned npm:pyright@1.1.414 (opencode's builtin pyright auto-starts from PATH — no stanza needed), alint lsp wired as the only explicit stanza. Note: the 'pin + stanza' phrasing does not hold for opencode+pyright (builtin auto-start). spec.md SHALL rules: the layer never installs servers at stamp time beyond the pin; servers auto-resolved outside mise are not wired unless pinned in layer fragments. backlog/decisions/ ADRs are deliberately separate from spec.md's 2026-10-11 Decision record snapshot table.

<!-- lore:01a19ff3-b423-7ba8-a0b9-afe92162d50f -->
* **prek layer merge invariant: never silently drop existing hooks**: Design invariant (fragments/prek-layer.toml header, recurring across sessions): the CLI merging \[\[repos]] entries into a stamped project's prek.toml must never silently drop existing hooks; it creates prek.toml if absent, and for a legacy .pre-commit-config.yaml it appends in that file's own format instead of replacing it. Rationale: fragments are additive layers over user project config — silently dropping hooks would remove enforcement the user already had.

* **merge.py deep\_merge: base-wins, never removes keys, tomli\_w strips comments**: merge.py invariants: deep\_merge is pure/idempotent/base-wins — 'the layer fills gaps, it does not overwrite choices the project already made'. Dicts: base wins on conflicting keys. Removal is text-level (regex); comment survival requires text-level composition, not TOML round-trips.

* **test\_lsp\_servers\_resolve\_through\_shims: alint Popen unbounded reads, Content-Length in chars not bytes**: Gotcha in tests/test\_stamp.py (~line 113): the alint branch uses Popen + unbounded p.stdout.readline()/read(length) with NO timeout — a slow or hung alint wedges the whole suite (no pytest timeout configured); the pyright branch has timeout=60. Trap: looks fine because tests pass with the pinned binary on ASCII paths. Fix: subprocess.run(input=payload, timeout=30) and compute length from data.encode('utf-8').

### Pattern

<!-- lore:01a19ff1-6e6d-7d52-8d40-567630920919 -->
* **Agent Skill Installation via dotagents**: Skills are authored via the skillet flow in ai-prompt-library (spec.md → SKILL.md). dotagents resolves skills from GitHub, so the push must precede installation. In the template's stamped bootstrap (fragments/mise-layer.toml), dotagents is mise-pinned (\`mise install "npm:@sentry/dotagents"\`) then installed project-scope via \`dotagents --project install\` — no dedicated dotagents-install mise task exists.

<!-- lore:01a19ff3-b466-7a88-9b4e-2a116b7dc0dd -->
* **agentic-project-template conventions: apt-ID comments, mise lint tripwire, template/ jinja-only**: agentic-project-template conventions: (1) comments in config files must reference the apt task ID (repo ai-rules; .prekignore cites apt-22); (2) \`mise run lint\` = \`uv run prek run --all-files\` — the natural tripwire for prek config regressions; prek pinned 0.5.2 in mise.toml; (3) template/ holds only .jinja files — no discoverable prek configs exist outside fragments/; (4) hooks installed via \`prek install\`; (5) repo test suite is merge-logic unit tests + stamp matrix — config-only changes need no new test. Test commands: \[tasks.test] = \`uv run pytest tests/ -x -q\`. The \[tasks.test-template] stamp matrix stamps $root/existing via \`layer --non-interactive\`, $root/fresh via \`new --base "$PWD" --non-interactive\`, and an update path (stamped with --set include\_git\_ai=true, git fixture commit, then \`update\`, then grep include\_git\_ai → 'update smoke OK (choices preserved)'); update smoke is skipped if the template repo has no commits.

<!-- lore:01a19ff1-6e5b-7355-a7d0-e1a30c94c833 -->
* **Backlog Task Management Workflow**: The project uses a structured task system defined in \`backlog/config.yml\` with statuses: To Do, In Progress, Done. Task files (e.g., \`apt-24\`) contain metadata like \`id\`, \`title\`, \`created\_date\`, and \`updated\_date\`. The \`backlog-py\` CLI does not use a \`task complete\` verb; closing a task is done via \`task edit -s Done --append-notes\`. The \`backlog\` directory contains \`archive\`, \`completed\`, \`decisions\`, \`docs\`, \`draft\`, \`milestones\`, and \`tasks\` subdirectories.

<!-- lore:01a1a30a-bf6e-716e-a463-5d863ec202f5 -->
* **fragments/mise-layer.toml: install+check only, install.run is a str, fslock guard**: fragments/mise-layer.toml carries ONLY layer-composition tasks: \[tasks.install] (bootstrap) and \[tasks.check] (alint + tombi lint gate) — pinned by test\_grab\_bag\_fragments\_are\_drained. Every tool's \[tools] pin and tool-specific task lives in fragments/tools/\<tool>/mise.toml, merged after this fragment in TOOL\_FRAGMENT\_ORDER. Header directive: 'Never put personal or machine-specific values here' — the stamped mise.toml must stay extendable (aboyeur / \`mise doctor project\`). \[tasks.install].run is a triple-quoted multi-line string; \_strip\_backlog\_wiring's isinstance(install.get('run'), str) check would silently no-op if it were an array. Bootstrap chain: TMPDIR/fslock writability guard (errors with sudo chown hint — aube/mise npm backend lock failure), \`mise install prek tombi "http:opencode" "github:asamarts/alint" "npm:pyright"\`, \`mise install "npm:@sentry/dotagents"\`, \`dotagents --project install\`, \`prek install --force\`, roborev install+init each wrapped in if-with-warn fallbacks, then \`mise run backlog-init\`.

<!-- lore:01a1a362-39af-79ab-8af5-379c78212f9b -->
* **opencode lsp section semantics: omitted disables all LSP, object form enables builtins (pyright rides PATH pin)**: opencode 2.0.32 LSP config (docs Nov 2026): omitting \`lsp\` disables ALL LSP servers; \`lsp: false\` disables all; object form \`lsp: {alint: {...}}\` keeps built-ins enabled while configuring custom servers. Per-server props: disabled, command (string\[]), extensions (string\[]), env, initialization. Template's lsp.alint section therefore enables builtins — builtin pyright starts when \`pyright\` is on PATH, so the npm:pyright mise pin alone is enough ONLY in combination with the lsp section (before apt-10, lsp was omitted → pyright never started even when pinned). npm:pyright@1.1.414 is node-based; mise's npm backend auto-installs node. Custom-vs-builtin shadowing for the same extension (alint's extensions list includes .py alongside pyright) is unspecified in docs. Docs caveat: LSP 'not always a net positive' — prefer CLI lint unless the project benefits. OPENCODE\_DISABLE\_LSP\_DOWNLOAD=true disables auto LSP downloads. Layer design context: \[\[01a1a345-fa33-75b1-98f2-a068d92749b5]].

* **opencode V2 pin: http:opencode, four-platform URLs+checksums, bump all together (apt-21)**: fragments/tools/opencode/mise.toml pins http:opencode 2.0.32 with four platform URLs + sha256 checksums (linux-x64/arm64, macos-x64/arm64; mirrors the anomalyco/tap opencode-v2 brew formula). * **Review a commit mid-merge via temp git worktree, never git stash**: When reviewing a commit while the working tree is mid-merge (UU files, conflict markers in stamp.py), the review target is the commit, not the worktree. Steps: 1. Confirm the provided diff is clean and matches the commit — check suspect files via \`git show \<sha>:\<file>\`. 2. Create a detached temp worktree at the commit SHA — never \`git stash\`; the tree is mid-merge and stash would destroy merge state. 3. Run the commit message's test claim there (e.g. \`uv run pytest tests/ -x -q\`) to independently verify "green" claims. 4. Exclude uncommitted merge/staged work from findings scope. Gotchas: - Conflict markers in the worktree look like commit bugs but are uncommitted in-progress merge state (e.g. main's backlog opt-out feature) — verify against the committed blob before reporting. Verify: - \[ ] \`git show \<sha>:\<file>\` has no conflict markers. - \[ ] Test suite passes in the detached worktree.
